## What the Launchpad does by itself after a wipe
- `/api/stats` reports `chainStatus` `ok`, `pending` (never read yet, about a minute after a deploy), `stale` (last good read older than 15 minutes, or a newer failure) or `unreachable`, with the real `chainError`. Its refresh is request-driven, so after idle the first call says `stale`.
- Reads pick a caller that exists, in this order: `MOI_READ_CALLER_ADDRESS` (taken on trust), the platform wallet if it exists, the account that sent the registry's first interaction. You rarely set anything.
- Wallet activation answers 503 `faucet_unavailable` and alerts the admin Telegram chat at most once an hour per process when all three registration wallets are gone. The page tells users nothing is wrong with their wallet.
- The dashboard compares the chain with the database per owner and shows "N agents need registering again". It computes this, so no list of old registries needs editing.

## Notes
- **L3.** Compare the chain's agent count with the database rows that carry a `registry_tx` (about 145 in August) to see whether the banner should fire. The unsigned build is `buildRegisterAgentInteraction` in `lib/moi/registry.ts`. The throwaway code that did this on 2026-09-15 (commit 942827a) is not in the repo and not recorded elsewhere; write the call fresh from that function.
- **L4.** `npm install js-moi-sdk@<v> js-moi-agent-registry@<v> --save-exact`. The registry package pins its SDK peer exactly, so one alone gives ERESOLVE. Keep the `overrides` entry that points that peer at the root SDK, and keep `js-moi-identifiers` as an explicit dependency. Never type a chain constant: read `KMOI_ASSET_ID` and `DEFAULT_FUEL_PRICE` from the SDK. `tests/chain-constants.test.ts` fails on a retired KMOI id or a fuel price below the floor. The strict `npm ci` is what the Docker build does: a lenient local install hid an ERESOLVE and every deploy failed from 2026-09-14.
- **L5.** A wiped account cannot recreate itself, so the script needs a sponsor that exists. The script's `MOI_REGISTRATION_GRANT` is the starting balance it gives each registration wallet. Its default is 0.5 KMOI, below the 1 KMOI floor for creating a participant, and the script treats "the account is visible" as success. The app then spends 10 KMOI from a registration wallet on each activation (its default; the deploy does not pass this variable), so give each wallet enough for a third of the sign-ups you expect, plus fuel. A zero sponsor balance is probably a funding at the faucet derivation path (the script's own comment): then add `MOI_SPONSOR_DERIVATION_PATH="m/44'/6174'/7020'/0/0"`. The operator gives the sponsor phrase with a no-echo prompt, never on the command line or in chat (`moi-devrel/references/consent-and-identity.md` section 4, rule 6), and Claude does not run the script or see the phrases. The script loads `MOI_REGISTRATION_MNEMONIC_1..3` from the environment of whoever runs it (it reads `.env` like the app), and DevOps holds them. ASK: Upendhar who runs it and how the values reach that person, never through chat.
- **L7.** The variable is under Settings, Secrets and variables, Actions, Variables (repo admin). The workflow rewrites the VM `.env` and takes about 4 minutes. The PR sets `DEFAULT_AGENT_REGISTRY_LOGIC_ID` in `lib/moi/registry.ts` to the new id, adds the id that just died to the "pinned out" test in `tests/chain-constants.test.ts`, and updates `tests/registry-id.test.ts`, so a deploy with the variable unset is still right. Leave `MOI_RPC_URL` alone: the code ignores any URL containing "voyage" or "devnet".
- **L8.** `"onchain":null` means the read is unavailable, not "unlisted"; it returned null on 2026-10-02 and 2026-10-03. Redeploy, by the operator: in `contracts/agent_market` run `coco compile` and `coco manifest convert` (the coco compiler: install it from the Coco docs and check `coco version`; Coco 0.9.3 targets PISA 0.8.2), then `bash contracts/agent_market/deploy-local.sh` (bash, because it reads the phrase at a hidden prompt with `read -s -p`, which zsh rejects). `MOI_DEPLOYER_SCAN=1` first prints the addresses of the derivation paths and calls no network; look each one up in the explorer to see which holds your funds. Then GATE: add `MOI_AGENT_MARKET_LOGIC_ID=${{ vars.MOI_AGENT_MARKET_LOGIC_ID }}` to `.github/workflows/deploy.yml` (not written today), set the variable, run the workflow, and update the default in `lib/moi/registry.ts`, `scripts/verify-purchase.mjs` and the tests that pin it. Verify with two funded wallets: list at 100, buy, `node scripts/verify-purchase.mjs <subscribe hash>`, and the seller gains the price exactly. v0.13.0 raised the default storage fund 10,000 times, "almost certainly why the AgentMarket deploy reverted" (commit 0471936). Whether the compiled manifest is valid on the new chain is not known. <!-- slop-lint:ignore -->

At c49afb7 they were still August's, so a user who dismissed them never sees a new one. The activation banner must stay above the stranded banner: a wallet that does not exist cannot re-register.

## Do not
- Rotate `AGENT_KEY_ENCRYPTION_SECRET` or regenerate secrets in the rush: every stored agent key becomes unreadable.
- Run the Telegram worker in production, or delete rows to tidy the lists.
- Run `probe-registry.mjs` or `_map.mjs` bare. Their defaults are `b97ce717`, the registry that froze on 2026-08-06. Set `MOI_AGENT_REGISTRY_LOGIC_ID` and `MOI_READ_CALLER_ADDRESS` first.
- Copy `docs/REGISTRY-C684F926-CUTOVER.md` blindly. It is a worked example of the August reset, with that month's ids and SDK. It is on `master` of the private repo (ASK: Rahul for access).
