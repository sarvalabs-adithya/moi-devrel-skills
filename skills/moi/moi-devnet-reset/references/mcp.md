## How the product reaches production
Merging to `sarvalabs/moi-mcp` deploys nothing. Production is a copy of the code in `sarvalabs/voyage-api` (private, owned by the Voyage team), branch `feat/moi-mcp`, folder `moi-mcp/`, deployed by the manual workflow "Deploy MOI MCP Gateway" (input `deploy_target`: `dev`, `production` or `both`). A reset therefore needs a change in two repos and a deploy run from the second. Hosts: write gateway `mcp.voyage.moi.technology` (OAuth), read gateway `mcp-read.voyage.moi.technology` (no sign-in). `mcp.moi.technology` does not exist. On the VM the app is in `/opt/moi-mcp` and runs as two pm2 processes, `moi-mcp-read` (port 8787) and `moi-mcp-write` (port 8788); the workflow touches only those two.

Read caller, step M3 (read-only, no install, needs `curl` and `python3`). Tesseract 0 of the registry holds its first interaction, MOI's import of agents (shown for the August registry in the Launchpad's cutover note), and the sender of an interaction on this chain is an account that exists:
```
curl -s -X POST https://dev.voyage-rpc.moi.technology/devnet/ -H 'content-type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"moi.Tesseract","params":[{"id":"<registry id>","with_interactions":true,"with_commit_info":false,"options":{"tesseract_number":0}}]}' | python3 -c 'import json,sys; print(json.load(sys.stdin)["result"]["ixns"][0]["sender"]["id"])'
```
Run on 2026-10-03 against the September registry, it printed an account id. With `"tesseract_number":-1` it prints the sender of the latest interaction instead, a different account, so keep `0`.

Full steps: `moi-mcp-ops/references/ship-a-change.md` Part B. PR #313 had been open with no review since 2026-09-23; it was closed as superseded by #320, which synced moi-mcp #27 and merged into `feat/moi-mcp` on 2026-10-14. Every PR to `voyage-api` builds a preview pair: write `https://pr-<N>-mcp.preview.voyage.moi.technology`, read `https://pr-<N>-mcp-read.preview.voyage.moi.technology`.
- **M7.** The workflow passes `WC_PROJECT_ID`, `PUBLIC_URL`, `MOI_NETWORK`, `MOI_DATA_DIR`, `HOSTED_PORT`, `LOG_LEVEL`, `NODE_ENV`, `MOI_READ_CALLER` (since #323, 2026-10-14, both gateways) and, for the read gateway, `MOI_RPC_URL`; nothing else. If the code default is not pinned also pass `MOI_AGENT_REGISTRY_LOGIC_ID`. `MOI_LAUNCHPAD_URL` must equal the Launchpad's `NEXT_PUBLIC_APP_URL` once the Launchpad tools are in the synced code. Before syncing newer code, compare the variables it requires (the table in `docs/handoff-infra.md` on `master` of `sarvalabs/moi-mcp`) with what the workflow passes: a variable the code requires and the workflow omits can stop the gateway at boot (inferred).
