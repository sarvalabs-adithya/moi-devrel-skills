# Content and demos: what goes stale outside the products

Facts are as of 2026-10-03. Clone reads are of the previous operator's clones (see each row for the branch and date). `ASK:` is defined in `moi-devrel/SKILL.md`. Back to `../SKILL.md`.

A reset kills every id, hash and "it works" that was true before it. Text that quotes one is wrong the moment the chain is re-initialised, and nothing warns you. Editing a file on disk is free. Pushing, posting, scheduling, uploading and editing a copy in a shared service are GATEs (the operator's explicit yes for that action).

## Find it
1. Run `bash "$SKILLS/moi-devnet-reset/scripts/id-grep.sh" <id> <path>...` once per dead id, over every working copy you hold: `moi-foundation/MOI-Webinars` (session folders, the release pack, decks), `sarvalabs/MOI-Website` (`blog/src/content/posts/`), the three docs repos and `js-moi-sdk`, the three product repos, and each demo repo below. An id can be the full 66-character form or the 8-character short name (`c684f926`); give the full id and the script also searches the short name (for a logic id) or the first 16 digits (for any other id, such as KMOI's). Add `--files` for a summary. The script never opens an env-named file, `.env.example` and `.env.production.example` included (it counts them in its summary). Those two hold names and comments only and may be read: `grep -n -i "<short id>" "<working copy>/.env.example" "<working copy>/.env.production.example"`.
2. Find text that is stale without quoting an id: `grep -rn -i -e "live on devnet" -e "since 11 September" -e "20K KMOI" -e "100K KMOI" <path>`. Add the words your own text uses: a count of agents, a version, a faucet amount, a date.
3. What the script cannot see: copies in Drive, Luma pages, Buffer drafts, scheduled posts, YouTube descriptions, Medium and Zenodo copies, Canva decks, and Otter or Gemini notes. List them and hand each owner the exact sentence (`../templates/messages.md`). The operator edits those copies.
4. Old ids that are meant to stay: the Launchpad test that pins the wiped id out (`tests/chain-constants.test.ts`), history files such as `docs/REGISTRY-C684F926-CUTOVER.md`, and the September post's sentence that tells readers to search their code for the old KMOI id. Do not strip them.

## Rules
- Quote the date and the node version beside any id or hash you write in text that will be read later: a reset removes the hash and the date is what keeps it meaningful.
- Write "live" only after the reads of `detect.md` and the claim-check live reads on the day. A read proves now, never since.
- Anything you cannot reach yourself is a draft for its owner.
