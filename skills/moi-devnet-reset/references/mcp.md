## How the product reaches production
Merging to `sarvalabs/moi-mcp` deploys nothing. Production is a copy of the code in `sarvalabs/voyage-api` (private, owned by the Voyage team), branch `feat/moi-mcp`, folder `moi-mcp/`, deployed by the manual workflow "Deploy MOI MCP Gateway" (input `deploy_target`: `dev`, `production` or `both`). A reset therefore needs a change in two repos and a deploy run from the second. Hosts: write gateway `mcp.voyage.moi.technology` (OAuth), read gateway `mcp-read.voyage.moi.technology` (no sign-in). `mcp.moi.technology` does not exist.

Read caller, step M3 (read-only, no install, needs `curl` and `python3`). Tesseract 0 of the registry holds its first interaction, MOI's import of agents (shown for the August registry in the Launchpad's cutover note), and the sender of an interaction on this chain is an account that exists:
```
curl -s -X POST https://dev.voyage-rpc.moi.technology/devnet/ -H 'content-type: application/json' -d '{"jsonrpc":"2.0","id":1,"method":"moi.Tesseract","params":[{"id":"<registry id>","with_interactions":true,"with_commit_info":false,"options":{"tesseract_number":0}}]}' | python3 -c 'import json,sys; print(json.load(sys.stdin)["result"]["ixns"][0]["sender"]["id"])'
```
Run on 2026-10-03 against the September registry, it printed an account id. With `"tesseract_number":-1` it prints the sender of the latest interaction instead, a different account, so keep `0`.

## Notes
- **M1.** The signature is "Could not load the MOI agent registry (logic 0x20000000c684f926...). It may not be deployed on this network. account not found". Read on 2026-10-02 and again on 2026-10-03: the live server still pointed at `c684f926`, the registry wiped on 2026-09-11.
- **M2.** At b38343d `master` pins the registry in `src/moi/registry.ts` (`DEFAULT_REGISTRY_LOGIC_ID`, overridable by `MOI_AGENT_REGISTRY_LOGIC_ID`) and already holds the September registry `2f3e9469`: commit 731a808 (2026-09-23) is an ancestor of `origin/master` in the previous operator's clone, which reached `master` with PR #21 on 2026-09-24. The `.env.example` comment on `master` still names `c684f926` as the default. The live server answered with `c684f926` because the production copy was synced before the pin and not since. On later local branches of the clone the file is `src/capabilities/reads/registry.ts`; local work that was never pushed: ASK: Adithya for a copy.
- **M4.** Dependabot opens one grouped PR for all `js-moi-*` packages and `js-polo`. Nothing from it merges by itself, because an SDK change can change what a user signs. Running the canary installs packages (a download, also a GATE). If KMOI's creator account no longer exists set `MOI_CANARY_ACCOUNT`. Replace any literal the SDK now supplies, such as the fuel price (50).
- **M6.** Title it like "chore(moi-mcp): sync subtree ..." from a branch such as `moi-mcp/sync-master`, base `feat/moi-mcp`, replacing the `moi-mcp/` folder. The command that copies the files is not documented. ASK: Adithya. PR #313 had been open with no review since 2026-09-23 (as of 2026-10-02). Every PR to `voyage-api` builds a preview at `https://pr-<N>-mcp.preview.voyage.moi.technology`.
- **M7.** The workflow passes only `WC_PROJECT_ID`, `PUBLIC_URL`, `MOI_NETWORK`, `MOI_DATA_DIR`, `HOSTED_PORT`, `LOG_LEVEL`, `NODE_ENV` and, for the read gateway, `MOI_RPC_URL`. If the code default is not pinned also pass `MOI_AGENT_REGISTRY_LOGIC_ID`. `MOI_LAUNCHPAD_URL` must equal the Launchpad's `NEXT_PUBLIC_APP_URL` once the Launchpad tools are in the synced code. Before syncing newer code, compare the variables it requires (the table in `docs/handoff-infra.md` on `master` of `sarvalabs/moi-mcp`) with what the workflow passes: a variable the code requires and the workflow omits can stop the gateway at boot (inferred).
- **M8.** Voyage-api, Actions, "Deploy MOI MCP Gateway", branch `feat/moi-mcp`. The job stops both gateway processes and starts them again: a short outage, and the write gateway loses in-memory OAuth authorization codes and in-flight signing calls. Who may trigger production is unknown. ASK: Rahul, Adithya. Check `https://<host>/.well-known/oauth-authorization-server` for `issuer`. Count the tools with `curl -s -X POST https://<host>/mcp -H 'content-type: application/json' -H 'accept: application/json, text/event-stream' -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'`, which answers as a server-sent event: 13 tools on the write gateway and 6 on the read gateway on 2026-10-02 and 2026-10-03, the 2026-09-23 sync.
- **M9.** claude.ai, Settings, Connectors, add `https://mcp.voyage.moi.technology/mcp` with OAuth; read KMOI supply; connect the wallet; create a small test asset; approve on the phone. The funding figure of 20,000 KMOI in `docs/deploy-checklist.md` predates v0.13.0 and is stale. Phone approvals cannot be automated.
